# Reviewing the private business-image drafts

The author identifies the supplied folder as KH-FUNSD. It contains 148 image
files and 146 distinct images after two exact duplicate pairs are collapsed.
Distinct image hashes do not establish independent documents, complete-page
coverage, or an exact mapping to the 158 documents in the published resource.
The Codex transcripts have not been independently human-reviewed.

At the author's subsequent instruction, a separate comparison uses these frozen
transcripts as operational ground truth, retaining literal `[ILLEGIBLE]` markers
and disclosing that they are machine-generated and unreviewed. Its scores measure
agreement with these references, not verified human transcription accuracy. See
the [new comparison protocol](../benchmarks/accuracy/BUSINESS_OCR_PROTOCOL.md).
This does not change the frozen historical OCR inputs or earlier authoring
records. The review workflow below describes how to produce stronger future
human-corrected references; it is not a claim that review has already happened.

## Establish the annotation unit

Keep the original files and their hashes. Identify actual documents, page
numbers, acquisition variants, near duplicates, and any repeated templates.
Record an explicit mapping instead of treating every filename as an independent
document. Preserve the existing source identities when recording corrections.

Decide the image coverage and reading-order rules before producing comparison
predictions. The current draft workflow receives the complete upright image.
For a full-image transcription, include readable headings, footers, logos with
text, stamps, marginal text, and acquisition overlays. Describe any exclusion
policy explicitly. If the intended task instead uses a document-only crop,
record that region, produce a new image hash, and freeze the crop before
evaluation. Never silently omit visible text from a full-image reference.

For ordinary business forms, use top-to-bottom block order and read table cells
row by row, left to right. Record exceptions for sidebars, rotated text or
overlapping stamps. These transcript-order rules do not supply bounding boxes
or semantic layout labels; those require separate annotation.

## Correct every image against its pixels

Open the private offline `review.html` generated by
`scripts/compile_business_reference_drafts.py`. Review all visible text at a
readable zoom, including regions omitted by the draft. Use its **Open original
image at full size** link to inspect small characters. Preserve Khmer and Latin
characters, literal spelling, numeral scripts, punctuation and monetary values.
Do not translate, expand abbreviations, repair a name from context, or replace
an uncertain amount with a plausible value. Preserve useful line boundaries;
the primary compact CER later removes whitespace and ZWSP after NFC.

Every draft starts with `human_reviewed: false`. A model's completeness flag is
not a review decision. The interface requires a reviewer name and an explicit
review choice. Editing clears completeness approval. An `[ILLEGIBLE]` marker
blocks complete-reference export. Keep unresolved spans and their notes in the
annotation archive; do not convert guesses or omitted text into an apparently
complete reference.

A second Khmer reader should independently check the image, preferably before
seeing the draft or first review, to find shared omissions and anchoring errors.
Resolve disagreements against the source image and retain the changes and
adjudication notes. If only one person reviews the images, disclose that limit
and do not describe the labels as independently double-reviewed.

Export a backup regularly. Browser storage preserves edits for the same source
identity but is not an archival copy. If storage is blocked, edits last only for
the current page session; export before closing it. Keep images, transcripts,
reviewer details and backups private unless a separate release is authorized.

## Freeze references before comparison

Verify that each included unit has complete image coverage, corrected text and
an explicit review record. Record unresolved or excluded units and reasons
before model predictions; do not exclude a difficult page because an OCR system
performs badly. Once a scored set is frozen, failed OCR calls retain that page's
full reference denominator.

Freeze source hashes, reviewed transcript hashes, annotation rules and
document-level train/development/test assignments. Group repeated pages and
acquisition variants of the same document together. Use verified template or
source groups where relevant and report remaining grouping uncertainty.
Do not label a random split of correlated images as unseen-document evaluation.

Keep test references away from inference prompts and comparison outputs away
from reference correction. Use separate development images for setup or tuning.
Record model files, software, native image processing, prompts, limits and
prediction provenance before test calls. Apply the declared scorer to every
selected page and independently recompute edit counts.

Report sample and document counts, source/acquisition composition, annotation
coverage, number of reviewers, disagreements, unresolved spans, exclusions,
empty outputs, errors and generation caps. Compact code-point CER is not
grapheme accuracy, semantic correctness, field-extraction accuracy or layout
quality. A modern-document result must identify its own population and cannot
be inferred from the separate historical handwriting comparison.
